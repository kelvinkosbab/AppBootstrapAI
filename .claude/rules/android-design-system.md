# Android Design System & Core UI Components

Without a design system, Compose code fills up with `Color(0xFF2962FF)`, `fontSize = 15.sp`, `padding(13.dp)`, and five `Button`s styled five ways — each one a dark-theme, font-scale, or rebrand bug. On Android the design system is mostly **Material 3 used properly**: one `AppTheme`, semantic color roles, the M3 type and shape scales, a few extended tokens, the icon vocabulary (see [`android-iconography.md`](./android-iconography.md)), and thin component wrappers — all in one module. To scaffold one or audit an existing app against it, invoke the **`android-design-system-pro`** skill.

## Where It Lives

- **One `:core:designsystem` module** (the Now in Android shape): theme, tokens, `AppIcons`, components, and their previews. Depends on Compose + Material 3 only — **never on `:feature:*` or `:data:*`**. Every feature module depends on it. See [`android-gradle-conventions.md`](./android-gradle-conventions.md).
- **Components take primitives, state, and lambdas** — never a ViewModel or a domain model from `:data`. If a component needs `UserEntity`, it's a feature composable, not a design-system one.

## AppTheme — Material 3, Dynamic Color With a Brand Fallback

```kotlin
@Composable
fun AppTheme(
    darkTheme: Boolean = isSystemInDarkTheme(),
    dynamicColor: Boolean = true,
    content: @Composable () -> Unit,
) {
    val colorScheme = when {
        dynamicColor && Build.VERSION.SDK_INT >= Build.VERSION_CODES.S -> {
            val context = LocalContext.current
            if (darkTheme) dynamicDarkColorScheme(context) else dynamicLightColorScheme(context)
        }
        darkTheme -> DarkColors      // generated by Material Theme Builder from the brand seed
        else -> LightColors
    }
    CompositionLocalProvider(LocalSpacing provides Spacing()) {
        MaterialTheme(
            colorScheme = colorScheme,
            typography = AppTypography,
            shapes = AppShapes,
            content = content,
        )
    }
}
```

- **Exactly one theme entry point**, applied once at the root (`setContent { AppTheme { … } }`) and in every `@Preview`.
- **Generate the light/dark schemes** (and medium/high-contrast variants if you support them) from the brand seed with **Material Theme Builder** — don't hand-pick 30 roles.
- **Dynamic color is a product decision.** Default on for utility apps; brands that must stay on-palette set `dynamicColor = false`, or keep dynamic color and pin only the brand-critical roles. Either way, the fallback scheme must be complete.
- **Material 3 Expressive** (`MaterialExpressiveTheme`, `MotionScheme`, expressive components) is opt-in behind `@ExperimentalMaterial3ExpressiveApi` — adopt deliberately in the theme, not ad hoc per screen.

## Tokens

### Color — use roles, never literals

- **Feature code reads roles**: `MaterialTheme.colorScheme.primary`, `onSurface`, `surfaceContainerHigh`, `error`, `outlineVariant`. Pair every container with its `on*` role (`primaryContainer` ↔ `onPrimaryContainer`) — mismatched pairs are where contrast fails.
- **No `Color(0xFF…)`, `Color.Red`, or `colorResource` in feature composables.** Literal colors don't follow dark theme, dynamic color, or contrast settings.
- **Brand or status colors M3 lacks** (success, warning, chart series) go in an **extended palette** provided through a CompositionLocal, with light and dark values:

  ```kotlin
  @Immutable
  data class ExtendedColors(val success: Color, val onSuccess: Color, val warning: Color)

  val LocalExtendedColors = staticCompositionLocalOf<ExtendedColors> {
      error("AppTheme not applied")   // fail loudly instead of silently using a default
  }

  object AppTheme {
      val extendedColors: ExtendedColors
          @Composable @ReadOnlyComposable get() = LocalExtendedColors.current
      val spacing: Spacing
          @Composable @ReadOnlyComposable get() = LocalSpacing.current
  }
  ```

- **`staticCompositionLocalOf`** for tokens that rarely change (palette, spacing) — cheaper reads; use `compositionLocalOf` only for values that change at runtime within a subtree.
- **Contrast**: 4.5:1 body / 3:1 large text for every role pair, in both themes — see [`android-accessibility-best-practices.md`](./android-accessibility-best-practices.md).

### Typography

- **Use the M3 type scale roles** (`displayLarge` … `labelSmall`) via `MaterialTheme.typography.titleMedium`. Customize the scale once in `AppTypography` (brand `FontFamily`, weights); feature code never sets `fontSize` / `fontFamily` directly.
- **Sizes in `sp`**, never `dp` — and test at 200% font scale (Android 14+ applies nonlinear scaling; layouts must reflow, not clip).
- **Brand fonts** via `res/font/` or downloadable Google Fonts (`GoogleFont.Provider`) — declare fallbacks.

### Shape, spacing, elevation

- **Shapes** from the M3 scale (`MaterialTheme.shapes.medium`) customized once in `AppShapes`. No `RoundedCornerShape(12.dp)` literals in features.
- **Spacing**: a small `@Immutable data class Spacing(val xs: Dp = 4.dp, val s: Dp = 8.dp, val m: Dp = 16.dp, val l: Dp = 24.dp, val xl: Dp = 32.dp)` read as `AppTheme.spacing.m`. A `13.dp` in a feature is a finding.
- **Elevation** is tonal in M3 — prefer `surfaceContainer*` roles over shadows for hierarchy.

## Components — Thin, Stateless, Slot-Based

```kotlin
@Composable
fun AppPrimaryButton(
    onClick: () -> Unit,
    modifier: Modifier = Modifier,
    enabled: Boolean = true,
    leadingIcon: ImageVector? = null,
    content: @Composable RowScope.() -> Unit,
) {
    Button(
        onClick = onClick,
        modifier = modifier,
        enabled = enabled,
        contentPadding = if (leadingIcon != null) ButtonDefaults.ButtonWithIconContentPadding
                         else ButtonDefaults.ContentPadding,
    ) {
        if (leadingIcon != null) {
            Icon(leadingIcon, contentDescription = null, modifier = Modifier.size(ButtonDefaults.IconSize))
            Spacer(Modifier.size(ButtonDefaults.IconSpacing))
        }
        content()
    }
}
```

- **Wrap Material 3 components; don't reimplement them.** A wrapper pins app defaults (shape, colors, padding) and delegates — it inherits ripple, focus, semantics, and min touch target for free. A `Box(Modifier.clickable { … })` "button" loses all of that.
- **API shape** (the Compose API guidelines): required params first, then `modifier: Modifier = Modifier` as the **first optional** parameter, then optional params, then a trailing `@Composable` content slot. Apply `modifier` to the root only.
- **Slots over configuration flags** — `content: @Composable RowScope.() -> Unit` instead of `text: String, showBadge: Boolean, badgeCount: Int, …`.
- **Defaults objects** for anything callers may tune: `object AppCardDefaults { val ContentPadding = PaddingValues(16.dp); @Composable fun colors() = … }` — mirrors `ButtonDefaults` and keeps call sites short.
- **Stateless and hoisted** — `value` in, `onValueChange` out ([`android-compose-best-practices.md`](./android-compose-best-practices.md)); parameters stable/immutable so components skip.
- **Accessibility built in** — merged semantics for compound rows, `Role` on custom controls, `heading()` on section headers. Fix it once in the component, every screen inherits it.
- **Start with the core set** a new app actually needs: primary/secondary/text buttons, icon button, top app bar, navigation suite wrapper, card, list item, text field, empty/error/loading states, and a dialog. Add components when a pattern repeats a third time, not speculatively.

## Edge-to-Edge and System Bars

- **Edge-to-edge is enforced** for apps targeting SDK 35+ on Android 15+. Call `enableEdgeToEdge()` in every Activity and handle insets: `Scaffold` passes `innerPadding`; standalone content uses `Modifier.windowInsetsPadding(WindowInsets.safeDrawing)` (or `safeContent` / `navigationBars` as appropriate).
- **Status/navigation bar contrast** follows the theme — don't hardcode `statusBarColor` (deprecated and ignored when edge-to-edge is enforced).
- Lists scroll **behind** the navigation bar with `contentPadding`, not cut off above it.

## Previews and Screenshot Tests

- **Every component has previews** wrapped in `AppTheme`, using the multipreview annotations: `@PreviewLightDark`, `@PreviewFontScale`, `@PreviewDynamicColors`, `@PreviewScreenSizes` (Compose UI tooling 1.6+). Cover default, disabled, loading, error, and long-text states.
- **A catalog** (an `:app-catalog` module or a debug screen, as in Now in Android) renders every token and component — the review surface for rebrands and Material upgrades.
- **Screenshot-test the design system** — Compose Preview Screenshot Testing (AGP plugin, still experimental), Roborazzi, or Paparazzi — in light/dark × 100%/200% font scale. Components are the highest-leverage place for screenshot tests; see [`android-testing-strategy.md`](./android-testing-strategy.md).

## Adopting in an Existing App

1. **Create `:core:designsystem`** with `AppTheme` wrapping today's colors so nothing visibly changes.
2. **Replace literals with roles/tokens as files are touched** — search `Color(0x`, `.sp)` outside typography, `RoundedCornerShape(`, `fontSize =`, `padding(` with odd values.
3. **Converge duplicate components** (each team's primary button) on one wrapper, screen by screen.
4. **Turn on edge-to-edge** and fix insets before bumping `targetSdk` to 35+.
5. **Enable dynamic color last**, once every screen reads roles instead of literals — otherwise the literals stick out.

## Common Pitfalls

- **Literal colors, sizes, and fonts in feature composables** — breaks dark theme, dynamic color, and font scaling.
- **Container colors without their `on*` pair** — unreadable text in one of the themes.
- **`compositionLocalOf` with a silent default** for tokens — missing `AppTheme` in a preview renders wrong instead of failing.
- **Reimplemented buttons/cards with `clickable` boxes** — lose ripple, focus, semantics, and 48dp targets. Wrap M3.
- **`modifier` applied to an inner child**, or not the first optional parameter.
- **Design-system module depending on `:data` / `:feature`** — inverted dependency.
- **Ignoring insets after enabling edge-to-edge** — content under the status or navigation bar.
- **Previews without `AppTheme`** — they show the default purple M3 palette and hide real bugs.
